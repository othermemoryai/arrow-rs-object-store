# Credential source joins

Source only, based on object_store `76baae165f7674b213b954c1acf5702df100ec3e`. Formatting and source diff checks ran; no compiler, test, container, network or provider job ran. Native's bridge implementation and its matching qualification remain separate. The active Native source and all earlier qualification inputs are unchanged.

This uses idea 7 and extends the existing source stage, HTTP service and token cache. It deletes the implicit credential-to-data dependency for the supported GCS read path. Credential work is still selected by the existing provider, validity and retry rules. The cache retains one immutable completion in its single existing entry, without retaining a live span, owner history or another registry. The comparison is the existing Native source-stage token and actual request/body guards; model judgement and query contents are untouched.

`HttpService::begin_read_stage(predecessors)` defaults to no stage; `HttpClient` delegates it. The supplied `ReadStage` contract carries its span, an explicit producer join and terminal completion. `ReadStageCompletion` is an opaque `Any + Debug + Send + Sync` token. Native owns the implementation, capture/population checks, ordinary same-query predecessor edges and the permitted cross-query terminal joins. Its token must become usable only after descendants settle; this donor does not implement or qualify that rule.

The existing credential provider gains one default helper returning `(Arc<Credential>, CredentialRead)`. `Ready` means no refresh or lock wait ran; `Completed` carries the caller's completed work; `Unavailable` covers an unsupported provider or missing completion. The default is unavailable, while static providers and skipped signatures are ready. The existing `get_credential` entry point and other provider consumers keep their behavior. External custom providers remain partial unless they implement this helper correctly; an unavailable GCS read creates a stage and explicitly joins no token, so an unsupported route cannot silently become a ready cache hit.

The cache tries both existing locks before awaiting. A ready hit creates no stage. A refresh scopes the actual fetch, including body parsing, and publishes its completion with the entry before releasing the writer lock. An actual waiter joins that entry's completion, including a missing token, and returns its own local completion rather than a foreign query's producer token. A refresh after a real wait first closes its waiter stage, then begins a new producer stage with the local waiter completion. Starting a refresh clears the old diagnostic completion, so a failed or canceled refresh cannot leave an earlier producer token looking like its completion. Credential values, TTL checks, fetch backoff and returned fetch errors stay on their existing paths. Cancellation and errors close open source stages without a successful token.

GCS GET and HEAD begin their data stage after the local credential completion. The existing response body wrapper retains that stage through EOF, error or drop; HEAD's empty body closes at its terminal response. LIST keeps the stage through the actual response body and XML handling. Successful source stages close only after that work settles. Writes and signing consumers keep the prior path and are outside this donor's coverage.

Hostname-to-IP metadata fallback cannot yet expose the prior settled attempt token. Its real IP request runs in a stage with an explicit missing prerequisite; the HTTP outcome is preserved, but dependency depth stays unavailable. A failed request is never marked successful. No parent or timestamp supplies the missing edge. Native owns the boundary hook that can replace this unavailable join, followed by a real fallback check; metadata fallback has no qualified depth claim here.

The HTTP producer/waiter test retains the same payloads and independently counts its three then four server requests. These checks validate the object_store callback plumbing; they do not substitute for Native ownership, graph reduction or token lifetime qualification.
